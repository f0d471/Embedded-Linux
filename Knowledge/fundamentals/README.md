# fundamentals：教程的前置知识与原文清单

## 这个目录干什么

两件事，一套章节：

1. **清道夫**：教程里出现一个不属于本章主线、以后还会反复出现的名词（ELF、
   sysroot、VFS、mmap……），在这里有一篇讲透；教程主线只留一句跳转。
2. **存档**：原资料里同一层次的罗列性内容（GCC 选项、Makefile 语法与函数、
   open 标志、ioctl 请求码、信号表……）在这里完整收进来。我们是在汲取原资料，
   原文的信息不能丢，只是换成我们的写法保存。

**不再分"讲解篇"和"手册篇"。** 所有篇都是同一套写法；有的实验多、有的清单多，
但体例相同，按教程需要排。

## 怎么用

- 不要求通读。教程指到哪一篇，读哪一篇。
- 每篇开头先写"你在教程哪里会撞见它"，再列"这篇要回答的三个问题"。
- 表格和清单是**查**的，不是背的；每条清单标出处（原书页码或本机实测）。
- 读完一篇的判据：能不看笔记回答开头那三个问题。

## 每篇的固定体例

    1  你会在哪里撞见它
       一个真实的教程场景：哪一篇、哪条命令、哪句报错。不从难点起笔，
       不假设读者已经懂。

    2  这篇要回答的三个问题
       只给问题，不给结论。读完回头答。

    3  先动手看一眼
       一条最小命令 + 本机真实输出。先看见现象，再讲原理。

    4  正文
       按"现象 -> 问题 -> 实验 -> 解释"推进，不按名词罗列。
       每个实验五步：目标 / 完整命令（参数注明在管什么）/ 真实输出 /
       逐行读（看哪一列、和哪个数对账）/ 一句结论。
       术语第一次出现就地定义；真实描述优先，比喻最多一句辅助。

    5  原文清单
       把原资料这一层的罗列完整收进来（选项表、函数表、标志位表），
       每条标出处与是否实测。这一节是"存档"，不是"选读"。

    6  带走
       5～8 条，逐条回答开头三个问题；外加一张"看到什么就先想到什么"。

    7  接下来
       相关篇章 + 教程里的位置。

## 维护规则

- 只写教程用到的篇；新增一篇必须同时改：本 README 索引、教程里的跳转、labs 目录。
- 术语审计：主线出现的新词，要么就地定义，要么指到本篇；"以后某阶段再讲"不算。
- 所有输出、数字、报错本机或板上实测，标日期；清单标原书页码。
- 每篇必须能回答开头三个问题；"带走"与问题逐条对应。
- 不按"讲解/手册"分类；清单是章节的一部分。
- 图：两个单元以内用 ASCII；分支/分层用 SVG，放 `fig/`。
