# fundamentals：教程的前置知识与速查清单

## 这个目录干什么

一套章节，干两件事：

1. **讲透名词**：教程里出现一个不属于本章主线、以后还会反复出现的名词（ELF、
   sysroot、VFS、mmap……），教程正文先就地讲到够用，想彻底弄懂的到这里读完整的一篇。
2. **速查清单**：同一层次的罗列性内容（GCC 选项、make 语法与函数、open 标志、
   ioctl 请求码、信号表……）集中保存在每篇的"速查清单"一节，查的时候不用翻教程。

所有篇都是同一套写法。有的实验多、有的清单多，体例相同，编号按教程用到的顺序排。

## 怎么用

- 不要求通读。教程指到哪一篇，读哪一篇。
- 每篇开头先写"你会在哪里撞见它"，再列"这篇要回答的问题"。
- 速查清单是查的，不是背的。每条标出依据：本机或板上实测（带日期）、man 手册、
  内核源码文件、芯片手册或标准文档。
- 读完一篇的判据：能不看笔记回答开头那几个问题。

## 每篇的固定体例

讲解写法与教程相同，以 [Knowledge/README.md](../README.md) 第二节为准：问题链推进、
新概念五步、不跳步、命令四步、容易想错的地方就地澄清。篇章结构如下：

    章首元信息    实验目录与实测环境（日期、系统、编译器版本）

    你会在哪里撞见它
                  一个真实的教程场景：哪一篇、哪条命令、哪句报错。
                  不从难点起笔，不假设读者已经懂。

    这篇要回答的问题
                  三个左右，只给问题，不给结论。读完回头答。

    0 先动手看一眼
                  一条最小命令加真实输出。先看见现象，再讲原理。
                  清单为主的篇（04 GCC 选项、06 make）用"先查三条"代替实验。

    1～N 正文    问题链，一节一个问题，节末"这一节搭好的积木"。
                  每个实验按命令四步写；判据写成可打勾的 [判] 块，能注错见红。

    速查清单      这一层的罗列内容完整收在这里，每条标依据与是否实测。

    回看          整篇的问题链从头串一遍：问题、答案、证据在哪一节。

    带走          逐条回答开头的问题；外加一张"看到什么就先想到什么"。

    接下来        相关篇章与教程里的位置。

## 维护规则

- 只写教程用到的篇；新增一篇必须同时改：本 README 索引、教程里的跳转、labs 目录。
- 术语审计：主线出现的新词，要么就地定义，要么指到本篇；"以后某阶段再讲"不算。
- 所有输出、数字、报错来自本机或板上实测，标日期；清单每条标依据。
- 每篇必须能回答开头的问题；"带走"与问题逐条对应。
- 配图规则同 Knowledge/README.md 第五节：ASCII 图多用；复杂的过程和结构做 SVG，
  放 `fig/`，命名 `<篇号>-<名称>.svg`。
