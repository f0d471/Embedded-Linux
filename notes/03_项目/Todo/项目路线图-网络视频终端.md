# 项目路线图：网络视频终端

这份文件定义 `project/` 这棵树的终点形态，并把从当前状态走到那里的过程切成刀。
它取代同目录原先的 [项目路线图-对齐电子产品量产工具.md](项目路线图-对齐电子产品量产工具.md)。

## 一、结论

**终点不再是"电子产品量产工具"，是一台网络视频终端。**

原终点的问题有三条，逐条记在第八节。一句话：它是纯用户态的 1750 行程序，
一行不进内核，三条总线（UART / I2C / SPI）一条不碰，
而"量产工具"这个场景是教学虚构的，真产线工具的主体（OTA、看门狗、
崩溃恢复、结果上报留档）它一件也没有。

保留的是它的**六层注册链表框架**。`struct + 函数指针 + 链表注册`
是 Linux 子系统的通用形状（`file_operations`、`platform_driver` 同形），
display 层已按这个形状落地并上板。骨架留，业务换。

同一副骨架上还要再挂一个业务：质检。它新增 inspect 与 record 两层，
并补齐本文件第八节点名"原终点一件也没有"的那四样（OTA、看门狗、崩溃恢复、
结果上报留档）。分刀见 [质检业务嫁接-inspect层与产品化](质检业务嫁接-inspect层与产品化.md)，
其刀号用 Q 前缀独立编号，不占用本文件的刀 0-11。

## 二、目标形状

一台接在显示器上、上电自启的设备：

    上电自启
      |
      +-- 摄像头采集                     V4L2, UVC 与 CSI 两个后端挂同一条链表
      +-- HDMI 显示器上实时显示           display 层 + PXP
      +-- 画面上叠加 OSD                  font 层
      |     时间戳 / 帧率 / 光强 / 姿态
      +-- 浏览器输入 IP 即可看实时画面      HTTP + MJPEG multipart
      +-- 光感或六轴触发自动录像存 eMMC     I2C / SPI
      +-- 串口下发命令控制                 UART
      +-- 鼠标点屏上按钮切页               input / ui / page 层
      +-- 全部参数走配置文件, 不改代码       config 层

产品原型是可视门铃 / 网络摄像机 / 工业巡检终端。

与原终点的关键差别是**纵向**：从设备树到驱动到 V4L2 子系统到用户态采集
到图像处理到 GUI 到网络协议到发行版打包，一条线打穿。
原终点只在最上面那一层横着铺。

## 三、平台硬约束

i.MX6ULL 是 6 系列里被砍得最狠的一颗，**无 GPU、无 VPU、无 IPU**，
Cortex-A7 单核。有两样东西可用：

    CSI    并行摄像头接口, 走 subdev 驱动架构, 不是别的 6 系列那套 IPU capture
    PXP    Pixel Pipeline, 能做色彩空间转换 / 缩放 / blending / 旋转
           这是本平台唯一的图像硬件加速

**没有 VPU 意味着 H.264 实时编码这条路封死。** x264 软编在 A7 单核上
只有个位数帧率且 CPU 打满，做出来是反面教材。

绕过去的办法：**UVC 摄像头芯片内部自带硬件 JPEG 编码器。**

    摄像头 --MJPEG--> V4L2 mmap 缓冲区
                        |
                        +--> 套 HTTP multipart 头直接发出       [零编码, 零拷贝]
                        |
                        +--> libjpeg-turbo 软解 -> PXP -> fb0   [只有本地显示才解]

推流路径一次编解码都不做，平台短板被绕开。
选 MJPEG 而不是 H.264 的理由就是这一条，写进 TechReports 时要保留这段推导。

**性能预期（全部未实测，上板实测优先于本节）**：
640x480 MJPEG 解码显示估计在 15~25 fps 量级，1280x720 可能掉到个位数。
spec 里不写 1080p。第一次跑出真数就回来把本段换成实测值。

    Makefile 第 24 行     SUBDIRS 加一个词

**注册链表在这里第一次有真实理由**：UVC 摄像头和 CSI 摄像头是两个完全不同的
底层实现，挂同一条链表，上层一行不改。原终点里这个设计是为教学而教学。

## 五、分刀施工

每刀的判据都要能注错见红：写完判据先故意改坏一处，看它红一次，再改回来。
没红过的判据不算数。判据脚本并入 `project/check.sh`，单层功能测进 `unittest/`。

### 刀 0  假摄像头后端（摄像头到货前可做，WSL 内完成）

照 display 层 `memdisp.c` 的路子，先写一个不依赖硬件的帧源：
从一个目录里按序读 JPEG 文件，冒充摄像头吐帧。
`video` 层的结构、链表、缓冲区生命周期全部在 WSL 里先跑通。

    判据  video 层在只有假后端时能完整 init -> 取 N 帧 -> exit
          每帧返回的长度等于文件长度, 首尾两字节是 FFD8 / FFD9
    注错  把某一帧文件截断 100 字节, EOF 判据必须失败

### 刀 1  video 层与 V4L2 UVC 后端

`VIDIOC_QUERYCAP` / `ENUM_FMT` / `S_FMT` / `REQBUFS` / `QBUF` / `DQBUF` 全套。
缓冲区走 `mmap`，不做 `read()` 那条慢路。

    判据  /dev/video0 协商出 MJPEG 与目标分辨率, 实际值与请求值逐项对账
          连抓 100 帧, 序号连续无空洞, 每帧 SOI/EOI 标记正确
          缓冲区地址在整个会话里保持不变, 证明确实是 mmap 而不是每帧拷贝
    注错  把 REQBUFS 的 count 改成 1, 连续抓帧必然出现 EAGAIN 或掉帧

### 刀 2  解码与显示

交叉编译 libjpeg-turbo（照 `00_基础/12 第三方库` 那篇 FreeType 的隔离构建法，
用 ELF Machine 与 SONAME 链验收 ARM staging）。解码后经 PXP 转 RGB 写 fb0。

    判据  解一张已知测试图, 板上像素计数与 x86 上解同一张图的计数逐项相等
          PXP 转换与纯软件转换两条路径输出逐字节相同, 耗时分别记录
    注错  把 PXP 的输出格式配错一位, 逐字节比对必须失败

### 刀 3  多线程流水线

采集 / 解码 / 显示分线程，中间是环形队列。队列满时的策略要显式定义
（丢最旧帧，不阻塞采集），并且可统计。

    判据  跑 60 秒, 采集帧数 = 显示帧数 + 丢弃帧数, 三个计数器闭合
          故意让显示线程 sleep, 丢帧计数必须上升而采集帧率不变
    注错  去掉队列的锁, 用 helgrind 或 tsan 必须报竞争

### 刀 4  OSD 叠加

时间戳、帧率、传感器读数叠在画面上。复用 font 层。

    判据  叠加区域的覆盖像素数与假显存预演的计数相等
          关掉 alpha 合成后颜色数必须塌缩（04 章 BUG_NO_ALPHA 已验过这个形状）

### 刀 5  net 层与 HTTP 推流

自己写 HTTP server，不用第三方库。`multipart/x-mixed-replace` 推 MJPEG。

    判据  curl 拉流, 收到的帧数与服务端发出计数相等
          每个 multipart 边界后的 Content-Length 与实际 JPEG 长度相等
          两个客户端同时拉, 互不影响帧率
    注错  把 Content-Length 写少 1, 浏览器必须花屏或断流

### 刀 6  UART 控制通道

`termios` 配置串口，自定义协议帧（帧头 + 长度 + 命令 + 校验）。
下发命令控制录像启停、切分辨率。

    判据  发 100 条命令收 100 条响应, 无粘包错解
          校验和错误的帧被拒绝且不影响后续帧同步
    注错  把校验算法改成永远返回 0, 坏帧拒绝判据必须失败

### 刀 7  传感器联动

I2C 读 AP3216 光感，SPI 读 ICM20608 六轴。光强低于阈值报警，震动触发录像。

    判据  遮住光感, 阈值事件触发且 OSD 数值有可观测变化
          静止时六轴模长稳定在 1g 附近, 容差写进判据

### 刀 8  录像与存储

MJPEG 帧序列封装存 eMMC。掉电安全（写完 fsync，索引最后写）。

    判据  录 10 秒, 文件里的帧数与录制计数相等, 每帧 SOI/EOI 完整
          录制中途强制断电, 重启后已落盘部分可完整播放

### 刀 9  GUI 四层：ui / page / business / config

量产工具那套框架的真正用武之地。预览页、回放页、设置页，鼠标操作。
配置文件决定分辨率、帧率、录像策略、报警阈值。

    判据  只改配置文件不重编, 分辨率与报警阈值生效
          配置文件缺字段时走默认值而不是崩溃
          页面切换后前一页的资源全部释放（valgrind 无增长）

### 刀 10  驱动层（下沉，BSP 含金量所在）

    10a  AP3216 字符驱动: 设备树节点 + platform_driver + cdev + 中断 + poll
    10b  CSI 摄像头: 设备树 + pinctrl + 时钟 + i2c 配 OV5640 寄存器 + subdev
    10c  把 10b 做成 video 层的第二个后端, 注册链表挂上去, 上层一行不改

10c 是整个项目的收束点：证明第四节那条设计真的成立。

    判据  两个后端都在链表上, 靠配置项切换, 上层代码 diff 为空
          rmmod 后设备节点消失且 lsmod 无残留

### 刀 11  Buildroot 打包

整套做成可烧录 rootfs，驱动作为 package 自动加载，应用开机自启。

    判据  新烧录的板子上电后无人干预即出画面
          rootfs 里不含交叉工具链的 glibc 版本冲突（03 章踩过：
          工具链 glibc 2.41 vs 板上 buildroot 2.30）

## 七、硬件与待确认项

已定的采购：USB UVC 免驱摄像头（跑通全链路，风险最低）+ CSI 模块 OV5640
（刀 10b 的深水区）。USB 先行：任何一步卡住都不会让整个项目停摆。

上板第一件事要确认三条，全部未确认：

    1  板上摄像头接口的实际形态。README 第三节的板载清单里没有列摄像头接口,
       而公开资料称本板支持 OV2640 / OV5640 / OV7725。以板子实物为准。
    2  ls /dev/snd 是否有声卡。JD 里"音视频"常连写, 有声卡才加 ALSA 那一路,
       没有就只做视频, 不硬凑。
    3  内核是否已编入 UVC 与 PXP 驱动, 没有就要重编内核, 这会提前触发刀 10 的环境。

**资料仓对这条路线零支援**：`07_驱动大全` 下只有 `01_inline_assembly` 一个目录，
全仓搜不到 v4l2 / uvc / ov5640 / camera 任何一个词。
主教材 PDF 也不覆盖。这条路要啃内核 Documentation 与 V4L2 API 手册。
好处是不存在"抄一遍等于没学"的风险，代价是进度比前三章慢。

## 八、原终点的三条问题（存档）

1. **无场景**。"电子产品量产工具"是教学虚构，真产线工具的主体是 OTA、
   看门狗、崩溃恢复、结果上报留档，成品版一件也没有。
2. **技术栈窄**。纯用户态 1750 行，不进内核，UART / I2C / SPI 一条不碰，
   网络只到 `recvfrom`。
3. **只有横向没有纵向**。全部代码在应用层同一个高度，往下深挖没有东西。

原路线图里判定为"有意偏离"的两条（头文件按层放、单份非递归 Makefile）
继续有效，不受本次换终点影响。原路线图第三节的 3.4 提到的 `config/` 目录
在本文件刀 9 落地。
