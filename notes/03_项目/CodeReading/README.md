# 代码精读

对 `project/` 下的文件逐行讲解。内容跟随最新代码状态，不保留历史版本的解释。

## 与技术分享的分工

| | TechReports/ | CodeReading/ |
|---|---|---|
| 讲什么 | 为什么是这个形状 | 这一行在干什么 |
| 组织方式 | 按时间线叙事 | 按代码结构静态展开 |
| 引用代码 | 只贴关键几行 | 一行不落 |
| 维护 | 写完定稿 | 代码变更后同步更新，含行号订正 |
| 读者 | 同行工程师 | 要接手改这段代码的人 |

同一个文件在两边都出现属于正常。被推翻的实现、改动经过、实测数据属于
TechReports，本目录只描述当前代码。

## 与主线章节的分工

`notes/` 的主线章节（`01_应用编程/` 等）是教材，它教的是通用知识：
`$(wildcard)` 是什么、`-MMD` 干什么用。本目录不重复教这些，
只讲"本仓这一行为什么用它、它在这里展开成了什么"。需要通用知识时链回主线章节。

## 五层覆盖要求

每篇覆盖以下五层。缺任何一层即为不完整。

### 第 1 层 记号

- 对象：语法写法本身。宏、可变参数、函数指针、`$(...)` 展开、shell 的 `$(...)`
  与 `${...}`。
- 要求：先给出这一行要回答的问题，再说明这个写法如何得到答案。不复述语法定义。
- 模板：`<这一行> 要解决的是 <问题>。写法用 <记号>，因为 <该记号与问题的对应关系>。`

### 第 2 层 语义

- 对象：执行时机的差异。预处理器在编译前就把代码删掉了、`make` 的变量是两遍展开、
  `-include` 与 `include` 的失败行为不同、shell 里管道每一段各自开子进程。
- 要求：每篇必须有一节把执行顺序摊平在时间轴上，逐步列出这一步在做什么、
  此刻哪些东西还不存在。
- 模板：时间轴表格或编号列表，一行一步。

### 第 3 层 结构

- 对象：目录树、调用方向、数据结构的字段排布、构建产物的落点。
- 要求：能画成图的一律画图，图紧随对应讲解，不集中堆在篇首。

### 第 4 层 意图

- 对象：上游保证的前提、已被提前排除的输入、这里为什么不做检查。
- 要求：逐处点明隐含前提及其来源。前提不成立时是什么后果，写出来。
- 模板：`此处假设 <前提>，由 <谁> 保证；若不成立，结果是 <后果>。`

### 第 5 层 实现

- 对象：由工具链行为决定的写法。看似冗余的一行、不能化简的表达式、
  换个等价写法就会坏掉的地方。
- 要求：说明化简后会发生什么。

## 单篇结构

1. 标题、对应代码路径与总行数。
2. 前置知识：链接到 `notes/` 的相关小节，随后不再解释这些概念。
3. 文件定位：这个文件在系统里的位置，谁包含它，它包含谁。
4. 正文分节，节标题标出代码行号区间，按代码顺序推进。
5. 执行顺序一节，满足第 2 层要求。
6. 容易读错的地方：列出与直觉不符的写法及其正确读法。
7. 消费者清单。

**行号区间必须与当前代码一致。代码增删行后，全篇行号一并订正。**
订正方法是 `grep -n '' <文件>` 重新对一遍，不靠记忆。
