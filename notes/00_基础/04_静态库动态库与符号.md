# 04 静态库、动态库与符号

被 01 章第 4 节用到。

## 一句话

符号就是"名字到地址"的一条记录；链接就是把所有 `.o` 里悬空的名字填上真实地址；
静态库是编译期填死，动态库是运行期才填。

## 一、先跟 ysyx 对上

    ysyx / NPC                          Linux 应用
    ------------------------------      ------------------------------
    全静态链接，一个 .bin 跑天下         默认动态链接
    klib 就是几个 .o 打包成 .a          libc.so.6 独立存在，多个程序共用
    链接后地址全部定死                   有一部分地址要等到运行时才知道
    没有 PLT/GOT                         有，而且是理解动态库的关键
    ld 脚本你自己写过（linker.ld）       ld 用默认脚本，但原理一样

    你在 ysyx 见过 "undefined reference to xxx"，
    那就是链接器说：有个名字我到处都找不到。这一篇讲的就是它背后的机制。

## 二、编译和链接的分工

    hello.c
       |
       |  gcc -c        编译：一个 .c 变一个 .o
       |                 这一步不需要知道 printf 在哪，
       |                 只在符号表里记一条 "我需要 printf"
       v
    hello.o    符号表:  T main        （我提供 main，在偏移 0x20）
                        U printf      （我需要 printf，不知道在哪）
       |
       |  gcc -o        链接：把所有 .o 和库拼起来
       |                 逐个解决 U，解决不了就报 undefined reference
       v
    hello      符号表:  T main
                        U printf@GLIBC_2.4    <-- 动态链接时它仍然是 U！
                                                  留给运行期解决

注意最后那行：动态链接的可执行文件里，`printf` 仍然是未定义的。
链接器只是确认了"libc 里确实有这个符号"，然后把活推给了动态链接器。

## 三、nm 的符号类型：一张表读懂

本机实测，一个包含各种全局变量的 `h.o`：

    $ arm-linux-gnueabihf-nm h.o
    00000000 B g_bss          int g_bss;                未初始化全局
    00000000 D g_init         int g_init = 1;           已初始化全局
    00000000 D g_str          const char *g_str = "abc"; 指针本身在 .data
    00000000 T helper         int helper(int x){...}     全局函数
    00000020 T main           int main(void){...}        全局函数
             U printf                                    需要，但没有
    00000004 d s_local        static int s_local = 7;    static 变量

    字母表（大写 = 全局可见，小写 = 只在本文件内）

    T / t    .text，代码
    D / d    .data，有初值的数据
    B / b    .bss，无初值的数据（见 01_ELF与程序加载 第三节）
    R / r    .rodata，只读数据
    U        undefined，本文件需要它但没有它    <== 最重要的一个
    W / w    weak，弱符号，可以被同名强符号覆盖
    A        absolute，绝对地址，不参与重定位

    大小写的区别就是 static：
        int  helper() {...}    ->  T helper     别的 .c 能调
        static int s_local     ->  d s_local    别的 .c 看不见

    注意 U 那行前面是空白，没有地址。因为它压根还不知道地址。

**这张表怎么用**：以后遇到 `undefined reference to 'xxx'`，第一步就是

    nm 你的所有 .o | grep xxx

看谁是 U（需要它）、有没有人是 T（提供它）。全是 U 就说明库没链上。

## 四、.a 和 .so

    静态库 libfoo.a                        动态库 libfoo.so
    ------------------------------         --------------------------------
    本质就是一堆 .o 打的包                  本质是一个特殊的 ELF (ET_DYN)
    ar rcs libfoo.a a.o b.o                 gcc -shared -fPIC -o libfoo.so a.c
    ar t libfoo.a 可以列出里面有啥

    链接时：链接器从里面挑出用得到的            链接时：只检查符号存在，
            .o 抄进你的程序                            记一条 NEEDED libfoo.so
            没用到的不抄

    结果：程序自包含，库删了也能跑             结果：运行时必须找得到 libfoo.so
          每个程序各带一份                            所有程序共用一份内存里的它

    嵌入式取舍见 01 章 4.3。

`-fPIC` 是什么：position independent code。动态库被加载到哪个地址是不确定的，
所以库里的代码不能写死绝对地址，得用相对寻址。这就是 PIC。
（PIE 是同一个思路用在可执行文件上，见 01 章 3.3。）

## 五、PLT 和 GOT：动态链接怎么把地址填进去

问题：`main` 里要调 `printf`，但编译时不知道 printf 的地址，运行时才知道。
难道要在运行时改写 `.text` 里的那条 `bl` 指令吗？

不行。`.text` 是只读且多进程共享的（见 01_ELF 第三节，LOAD #1 权限是 R E）。
改它就破坏共享，还得给代码段加写权限，安全上不可接受。

解法：**代码里的跳转目标写死，但让它跳到一个跳板；跳板去查一张可写的表。**

    .text（只读，共享）        .plt（只读）              .got.plt（可写，每进程一份）
    ---------------------      --------------------      ---------------------------
    main:                      printf@plt:               [ printf 的真实地址 ]
      ...                        ldr pc, [ip, #偏移] ---> 由 ld.so 在启动时填进来
      blx printf@plt  --------->                               |
      ...                                                      v
                                                        libc.so.6 里 printf 的代码

本机实测，两处证据。

第一处，`main` 调的确实是跳板不是 printf 本身：

    $ arm-linux-gnueabihf-objdump -d h | sed -n '/<main>:/,/^$/p'
     540:  f7ff ffe4   bl   50c <helper>            <-- 自己的函数，直接跳
     54e:  f7ff ef4e   blx  3ec <printf@plt>        <-- 库函数，跳到 @plt 跳板

第二处，跳板干的事就是"从表里取地址然后跳过去"：

    $ arm-linux-gnueabihf-objdump -d -j .plt h
    000003d4 <__libc_start_main@plt>:
     3d4:  add  ip, pc, #0, 12          \
     3d8:  add  ip, ip, #126976          |  三条指令算出 GOT 表项的地址
     3dc:  ldr  pc, [ip, #3068]!        /   最后一条：把表项里的值装进 pc
                                            装进 pc 就是跳转（01 章讲过 pc 是通用寄存器）

    ldr pc, [...] 这一条就是全部秘密：跳到哪，取决于那个内存单元里存的是什么，
    而那个内存单元（GOT 表项）是可写的，ld.so 想填什么就填什么。

**延迟绑定（lazy binding）**：ld.so 启动时并不会填完所有表项，
初始值指向一段"解析器"代码。第一次调用 printf 时才真正去查找并回填，
第二次开始就直接跳过去了。好处是启动快，一个用不到的函数永远不用解析。
（`LD_BIND_NOW=1` 环境变量可以关掉延迟绑定，改成启动时全部解析。）

## 六、工具表

    工具         看什么                    常用法
    ----------   ----------------------    -------------------------------
    nm           符号表                    nm a.o / nm -D a.so（动态符号）
    readelf -d   .dynamic 段               看 NEEDED、SONAME、RPATH
    readelf -r   重定位表                  看哪些位置需要被填
    objdump -d   反汇编                    -j .plt 只反汇编某个 section
    ldd          递归列出依赖的所有 .so    只能对本机架构的文件用
    ar t         静态库里有哪些 .o
    strings      文件里的可打印字符串      快速看有没有某个路径/版本号

    交叉编译产物要用带前缀的版本：
        arm-linux-gnueabihf-nm / -readelf / -objdump
    直接用本机的 nm 有时也能读，但遇到 ARM 特有的段会报错。
    ldd 对 ARM 文件不能用（它是靠实际跑一遍来列依赖的），改用 readelf -d。

## 七、亲手验证

先自己想：

    问题 1  怎么造出一个 U 符号？
            线索：声明一个函数但不实现它，然后 gcc -c（只编译不链接）。
    问题 2  怎么证明 static 让符号从大写变小写？
    问题 3  怎么证明 main 调的是 PLT 跳板而不是 printf 本身？
            线索：反汇编 main，看 bl 的目标名字。

答案：

    cat > t.c <<'X'
    int g_init = 1;
    int g_bss;
    static int s_local = 7;
    int helper(int x) { return x + s_local; }
    extern int nobody(void);              /* 只声明不实现 */
    int main(void) { return helper(g_init) + nobody(); }
    X

    arm-linux-gnueabihf-gcc -c -o t.o t.c    # -c 只编译，产出 .o
    arm-linux-gnueabihf-nm t.o               # 看符号表

    arm-linux-gnueabihf-gcc -o t t.c         # 完整链接，这一步会失败
    # 预期：undefined reference to 'nobody'

    # 问题 3
    arm-linux-gnueabihf-gcc -o h h.c         # 用带 printf 的那个 h.c
    arm-linux-gnueabihf-objdump -d h | sed -n '/<main>:/,/^$/p'
    #                              ^^ disassemble
    #                                        sed 取 main 到下一个空行

[判] 判据

    [ ] nm t.o 里 nobody 是 U，helper 和 main 是 T，s_local 是小写 d
    [ ] 完整链接时报 undefined reference to nobody，
        且报错来自 ld 不是 gcc（看报错前缀）
    [ ] 反汇编 main，调自己的函数是 bl <helper>，调库函数是 blx <printf@plt>
    [ ] objdump -d -j .plt 里最后一条指令是 ldr pc, [...]

    注错见红：把 extern int nobody(void); 那行的 extern 去掉、改成
        int nobody(void) { return 0; }
    再跑一遍 nm，nobody 应该从 U 变成 T，链接也不报错了。
    没变说明你编的不是改过的文件。
