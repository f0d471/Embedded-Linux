# 00 基础通用知识

## 这个文件夹解决什么问题

主线章节（01、02、03...）讲的是"这一章的事"，遇到通用名词只能一笔带过，
不然主线就断了。但一笔带过的结果是：你看到 `s0`、`sysroot`、`PLT` 这种词，
知道它在句子里的位置，却不知道它是什么。

所以约定：

    主线章节里出现一个名词，如果它
        不属于本章主线            例如 ARM 寄存器编号不属于"工具链"这一章
        且以后还会反复出现        例如 ELF、系统调用、动态库
    就在这里单开一篇，主线里只留一句话加一个跳转。

用到就加，不预先写全。没被任何一章引用过的篇章不要写。

## 没看懂时怎么兜底

每篇正文前都有固定的 **“没看懂也先记住”**。第一遍跟不上推导时，读完这一块
就可以先继续主线；下次碰到相关名词或报错，再回来扫一遍。先让结论眼熟，
原理可以在后续阅读和实验里慢慢补上。

每块都直接给答案：

- **先带走这 5 条**：本篇最少要记住的判断，术语就地用一句话解释。
- **看到什么，就先想到什么**：把名词、输出或报错对应到第一步判断和操作。
- **反复看这 3 组问答**：答案直接展示，不折叠，也不要求先做出题才能往下读。

复习时可以只看问答；愿意自测就遮住答案，想不起来直接看。会复述结论和会解释
原理是两种进度，记住答案不需要等实验全部做完，记住了也不代表已经完成实验验证。

## 体例

2026-09-08 换代。旧体例（一句话 -> 对照 ysyx -> 展开 -> 给几条命令）
被推翻，原因有三条，写在这里防止再犯：

    问题 1  术语凭空出现
            旧版 01 篇第一句就用 program header、e_entry、mmap、ASLR 讲"对照"，
            但这些词一个都没定义过。搭桥本身成了新门槛。

    问题 2  拿"你学过"当"你会了"
            有 ysyx 和龙芯 SoC 的底子，不等于每个概念都清楚。
            对照只能当辅助，**不能替代从零讲一遍**。

    问题 3  验证是玩具
            旧版给"先自己想"三个问题 + 几条命令 + 打勾框，
            没有输出长什么样、看哪一列、看到之后能推出什么。
            结果是做到一半就卡住（旧 01 篇四条判据实际只勾了两条）。

新体例，每篇按这个结构写：

    1. 前置声明：读本篇要先读哪篇。写明"不需要其他前置知识"
       正文前固定加“没看懂也先记住”：5 条结论 + 现象/第一反应表 + 3 组带答案问答。
       读者可以先记答案再读推导；块末指明想补原理该回到哪一节。
    2. 从上一篇留下的问题接上，让新概念是被"逼出来"的，不是空降的
    3. 主体由若干个实验组成，每个实验固定五步：

         先自己想   给目标和线索（工具叫什么、开关的首字母是什么意思），
                    不给现成命令
         动手       完整命令，**每个参数注明它在管什么**，
                    以及"为什么是这条命令"的推理过程
         贴输出     本机真跑的原始输出，不省略、不美化
         逐行读     指名道姓说看哪一列哪一行，那个数字是什么意思，
                    和前面哪个数字能对上账
         下结论     从现象推出一句话，并说明它在实际工程里意味着什么

    4. 判据：每个实验一组，可勾选。至少有一条是"两个数字必须相等"的对账型
    5. 注错见红：故意改坏，写明**实测的**失败现象。没红过的判据不算数
    6. 被谁用到

硬规矩：

    - 每篇必须有上述兜底块，不能用“读完你会知道什么”或待勾选判据代替。
      直接写出应该带走的答案，不折叠、不把“先自己想”作为查看答案的门槛。
      结论用短句，必要术语就地解释，适用条件紧跟结论；不能把本机某次耗时、
      地址、缺页次数背成通用规律。新增或修改正文结论时，同步更新兜底块。
    - 每个术语第一次出现必须就地定义，用 > 引用块标出来。
      一篇里不许出现"后面会讲"的名词超过两个；兜底块用同行短释义，正文仍保留引用块定义
    - 所有输出、数字、报错都是本机实跑的，写明日期和工具链版本。
      写笔记的人要先自己完整跑一遍，再把过程写成手把手的步骤
    - 对照 ysyx / RISC-V / 龙芯 SoC 的内容一律放在**靠后**的"顺带一提"，
      并注明"没做过也不影响，跳过即可"。正文不许依赖它
    - 能画图就配 ASCII 图，尤其是"哪一步在内核里、哪一步在用户态"这种边界
