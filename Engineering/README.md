# Engineering：工程文档

`Project/` 这棵代码树与 `Knowledge/` 教程改造的工程文档。

和 `Knowledge/` 的关系：`Knowledge/tutorials/`、`Knowledge/fundamentals/` 是教材，
读者是正在学这些知识的人，按教程章节推进；本目录是工程文档，读者是要接手改
`Project/` 的人，按代码结构和开发时间线推进。同一件事在两边都出现是正常的，
但落点不同：教程讲"这个知识点怎么学会"，这里讲"这段代码为什么长这样、
这一行在算什么"。

## 目录

| 目录 | 收录范围 | 维护方式 |
|---|---|---|
| [TechReports/](TechReports/) | 每个工作点的开发过程 | 一层一个系列，完成一个工作点增加一章，写完定稿 |
| [Todo/](Todo/) | 学习与项目的总路线；不再按工作点分文件 | 工作点完成后进 TechReports；总路线长期存在，删除条件见文件第十四节 |
| [Bugs/](Bugs/) | 未修复的在产缺陷 | 修复后删除文件，内容并入 TechReports |

`Todo/` 当前只有一份：[学习与项目路线](Todo/学习与项目路线.md)。两个学习阶段的
顺序、Knowledge 排期、Project 的层与刀、遗留账全在这一份里。工作点完成后按下面
的流转规则进 TechReports，不再在这里另开文件。

`Bugs/` 当前记录一项输入层缺陷：[同一 SYN 帧内指针与普通键共存时丢键](Bugs/01-同帧指针与普通键丢事件.md)。

## 流转规则

1. 开工前在 `Todo/学习与项目路线.md` 对应阶段里写清要解决什么、判据是什么。
2. 过程中的实测数字回填到该文件的阶段表与刀表，不另开 Todo。
3. 过程中出现修不掉的缺陷，在 `Bugs/` 另开一条，注明现有判据为什么没覆盖到它。
4. 工作点完成并且 `Project/check.sh` 全绿之后，在 `TechReports/` 对应系列增加一章，
   并回总路线勾状态。
5. 总路线本身不按工作点删除；它的删除条件写在文件第十四节。

## 项目规则：提交即更新文档

**每一次 commit，都要在同一次 commit 里把它影响到的文档改完。**
文档滞后于代码，等价于文档不存在：读者会照着旧描述去找一段已经不在那里的东西，
比没有文档更浪费时间。

对照表如下。左列发生了，右列就必须在同一个 commit 里改到位。

| 改动 | 必须同步的文档 |
|---|---|
| 完成一个工作点（一层从空壳变成有实现、构建系统换法、判据体系变化） | `TechReports/project/` 增加一章，并在 `Todo/学习与项目路线.md` 里勾状态 |
| `check.sh` 判据条数变化 | 更新仓库根 `README.md` 与 `Project/doc/验证流程.md` 的 PASS 数 |
| 发现一个改不掉的缺陷 | `Bugs/` 新增一条，写明现有判据为什么没覆盖到 |
| `Knowledge/` 某章教程完成或改造 | 仓库根 `README.md` 的进度栏 + `Todo/学习与项目路线.md` 的教程状态 |
| 新增/重排 `labs/` 实验目录或判据 | 所在教程篇的判据数字 + `fundamentals/README.md` 篇目表（若涉基础篇） |
| 教程引用的路径、文件名、章节号变化 | 引用方教程篇就地订正，不留死链 |

三条硬约束：

**先讲行为，再给术语。** 面向初学者的正文和代码注释，第一次出现 `fd`、`stderr`、
`dup2`、`mmap` 等名字时，必须先说明"输入是什么、执行后能观察到什么、失败时怎样"，
再补技术名称和内部原理。不能用"2 号槽""换一格""指向 `struct file`"这类简称
代替解释。代码标识符可以保留，但读者不应为了看懂一句注释再去查另一篇术语表。

**行号与引用必须准。** 文档里引用代码位置时，行号要重新 `grep -n '' <文件>`
对一遍，不靠记忆；引用其他文档时用相对链接，目标改名后引用方在同一个 commit 订正。

**判据数字必须是跑出来的。** 文档里出现的 PASS 数、体积、行数、耗时，
一律以本机或板上实测为准。改完代码先跑 `bash Project/check.sh`，
拿到的数字再写进文档。

## 检查方式

提交前自问三条，答不上就是文档没跟上：

    1. 这次改动算不算一个"工作点"？算的话 TechReports/ 那一章写了吗？
    2. check.sh 的 PASS 数变了吗？变了的话根 README.md 和 Project/doc/验证流程.md 改了吗？
    3. 这次改的教程篇，被别处引用的路径和章号还对吗？
