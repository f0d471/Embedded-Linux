# 开发环境

本目录文档只描述"当前怎么把它跑起来"，不记录过程（过程在 Engineering）。
两条总原则：**结论带出处**（文件路径加行号，或文档名加节号）；**没有实测的数字
标明是估算**。

## 1. 标准工作流

日常开发在 WSL Ubuntu 里做（x86 gcc 跑逻辑），只有上板验证时才连板子。

    WSL 侧：   写代码 -> make（x86） -> bash check.sh（判据）
               -> make CROSS=arm-linux-gnueabihf- LDFLAGS=-static（攒 ARM 产物）
    上板侧：   Tools/serial-board.ps1 经串口登录板子、传文件、收输出
               （板子左侧**下面**那个 micro-USB，6 号口，CH9102 -> Windows COMx；
               上面 5 号是 OTG，插了只响提示音不出 COM 口）

## 2. 工具链与依赖

WSL Ubuntu 26.04 已装（2026-09 起）：

    gcc / make / ccache             本机 x86-64，gcc 15.2.0
    arm-linux-gnueabihf-gcc         交叉编译器 15.2.0（含 binutils：readelf/nm/objdump）
    strace / file / bc

**故意不装 qemu-user-static**：装了它 x86 上能直接跑 ARM 程序，教程 01 篇
"必须报 Exec format error"的判据就失效了。

外部依赖只有一个：FreeType 2.10.2 源码包。Makefile 的 `FT_TARBALL` 默认指向
资料仓 `01_all_series_quickstart-master/04_.../source/10_freetype/` 下的 tar.xz
（相对路径 `../../01_all_series_quickstart-master/…`），check.sh 里用绝对路径
覆盖（因为 check_core 会把 Project/ 复制进 /tmp，相对路径会断）。资料仓不在
预期位置时，用环境变量 `FT_TARBALL=<绝对路径>` 指过去。

板子出厂系统关键事实（2026-09/10 实测）：Linux 4.9.88、buildroot 2020.02、
glibc 2.30；出厂 GUI 是 mxapp2（Qt linuxfb），占满 fb0；板上有 strace/file/
tar/gzip/base64/sha256sum/python3/curl，**没有 socat**；bash 无 UTF-8 locale，
串口里敲的命令不能带中文（readline 把 >=0x80 字节当 Meta 组合键）。

## 3. 静态链接（上板产物硬性要求）

WSL 的交叉工具链 glibc（2.41）比板上（2.30）新。动态链接的产物上板在
`execve` 阶段就报 ``version `GLIBC_2.xx' not found``，一行应用代码都没执行。
所以上板一律：

    make CROSS=arm-linux-gnueabihf- LDFLAGS=-static

Makefile 里 `LDFLAGS :=` 是空值定义，命令行变量优先生效；层内需要追加链接选项时
必须写 `override LDFLAGS += ...`（input 层的 `-pthread` 是现成例子），普通 `+=`
会被命令行变量整个顶掉。代价：体积 72 KB -> 495 KB，串口上传变慢，可接受。

`-static` 要放在 `-o` 前面，放到后面会被当成输出文件名。

## 4. 上板流程与板上备忘

    1. 板上停出厂 GUI：   killall mxapp2（1 秒内可能还活着，pidof 确认）
    2. 传静态产物：        Tools/serial-board.ps1 -Download（gzip -> base64 分块，
                           板上逐块 sha256 校验后才追加；串口会静默丢字节，
                           整文件最后再比一次哈希，丢了自动重传该块）
    3. 跑之前 chmod：      chmod +x /tmp/lab/*（串口重传会把执行位抹掉）
    4. 跑程序 / dd 回读：  显示类实验用 dd if=/dev/fb0 ... 抓显存，
                           交给 unittest/count.sh（板上 GNU Awk）数像素
    5. 恢复出厂 GUI：      重启 mxapp2（/etc/init.d/S99myirhmi2）

板上接口备忘（实测）：

    AP3216C 在 i2c-0 @0x1e，无设备树节点（出厂系统不认），
    用户态 i2c-dev 直读是唯一通路；
    ttymxc0 是控制台，不能拿来发数据；ttymxc2 / ttymxc5 空闲可 probe；
    fb0 出厂 1024x600x32，插 HDMI 后 sii902x 改成 1280x720x16 60Hz；
    /dev/input/event1 是 gpio-keys（板上唯一真实 evdev 源，没接 USB 鼠标）。

## 5. WSL 侧的限制与对策

- WSL 没有 framebuffer/evdev 实例（`/proc/devices` 有 29 fb 但 open 报 ENODEV），
  所以判据用内存后端：`DISP_DEV=mem FONT_DEV=builtin INPUT_BACKEND=replay`
  （check.sh 已固化）。真后端（fb/evdev/netinput）只有板上验得了。
- 设备文件实验（mknod）在 root 的 `~/` 下做，不在 `/mnt/e`（Windows 盘
  不支持设备节点，root 也 EACCES）。
- `/mnt/e`（9p 文件系统）mtime 精度和 IO 性能都差，make 会漏判重编——
  check_core.sh 把整个工程复制进 /tmp 再跑，原因之一就是这个。
- 从 Windows 侧调 WSL：PowerShell 或 `MSYS_NO_PATHCONV=1 wsl.exe -e bash -c '…'`；
  裸 Git Bash 调 wsl 会把 `/mnt/...` 参数转成 Windows 路径。`wsl -u root` 免密。
