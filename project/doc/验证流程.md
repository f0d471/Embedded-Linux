# 验证流程

验证范围、状态与判据数字的唯一规则。AGENTS.md 的"提交前跑 check.sh"指的就是
本文件的执行方式。

## 1. 判据体系

三套件分文件维护，check.sh 汇总：

| 套件 | 覆盖 | 判据数 |
|---|---|---|
| check_core.sh | 框架（common/display/层注册/构建） | [1]～[10]，52 条时代的主干 |
| check_font_input.sh | font/input 两层（含 netinput、线程） | [11]～[17] |
| check_gui.sh | config/ui/page/business 四层 + items + 分层边界 | [18]～[23] |

总入口 `bash check.sh` 固化确定性后端（`DISP_DEV=mem FONT_DEV=builtin
INPUT_BACKEND=replay`），依次跑三套件、汇总各自 `PASS=n FAIL=n SKIP=n`，
打印 `TOTAL`；三套件退出码全 0 且总 FAIL=0 才算过。会把工程复制进 /tmp 跑
（避开 /mnt/e 的 mtime 精度问题），所以 FreeType 依赖用绝对路径 `FT_TARBALL`。

fundamentals/labs 的判据在 `knowledge/labs/` 各目录的 check.sh，跑法见
knowledge/README.md 第三节，与本文件同规则。

## 2. 档位

| 档位 | 范围 | 什么时候 |
|---|---|---|
| quick | 与改动相关的单个套件（改 input 只跑 check_font_input.sh） | 开发中随时 |
| acceptance | `bash check.sh` 三套件全量 + ARM 静态产物可构建 | 每个 commit 前、工作点收口 |
| 板测 | 上板实跑（流程见 doc/开发环境.md 第 4 节）：停 mxapp2 -> 传静态产物 -> 跑 -> dd 回读显存/串口输出对账 -> 恢复 mxapp2 | 工作点声明"板上验证过"之前 |

同轮相同输入与参数的检查执行一次；必需项没跑就单列为未完成，不汇总成
"全部通过"。**SKIP 不算通过**：SKIP 是"本轮没验"，必须在结果里点名。

## 3. 判据的规则

- **注错见红**：每条判据都要配一次"故意改坏，判据必须 FAIL"的演示。
  新增判据时当场演示注错；改判据时重演。
- **期望值与检查器分离**：期望值手写并注明出处（笔记/教程里的实测数字），
  检查脚本是另一份实现，两者对不上即 FAIL。
- **数字进文档的规则**：文档里出现的 PASS 数、体积、耗时一律以实跑为准。
  改完代码先跑 `bash check.sh`，拿到的数字在同一次 commit 里更新到
  根 README 进度节与本文件的基线行。
