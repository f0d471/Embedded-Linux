# knowledge：知识库

仓库的重心。定位一句话：**教程完全自足**。原书 PDF 与视频的知识已经提取进
这里，学习不需要再看视频、翻原书；原始资料（sources/）只作改写素材与最终兜底。

## 目录

| 目录 | 收录范围 | 维护方式 |
|---|---|---|
| [tutorials/](tutorials/) | 教程，按原书篇章与章号组织 | 一章一篇；每完成一篇，在 Engineering/Todo/knowledge教程化路线.md 勾状态 |
| [fundamentals/](fundamentals/) | 基础知识：讲解篇 + 手册篇 | 用到才加，不预先写全；没被任何教程引用的篇不开 |
| [labs/](labs/) | 课程实验与判据脚本 | 按教程章号建目录，每篇配 check.sh |

三层的关系：教程是主线（"这件事为什么存在、怎么一步步做出来"），
fundamentals 是前置与案头手册（"这个名词是什么"“这个选项有哪些"），
labs 是动手与判据（"做没做对，机器说了算"）。教程正文里遇到 fundamentals
覆盖的名词，用一句 `[基础]` 跳转，不展开；遇到罗列型内容（成堆的选项、
标志位、函数清单），指到手册篇，不逐条抄进正文。

## 一、教程体例（tutorials/）

2026-10-16 起生效，覆盖旧体例。**反转的一条**：旧体例的"先自己想，不给命令"
作废——教程里每条命令、每段代码都**完整给出**，因为读者不再可能去翻原书对照。
旧体例的"过滤器/过滤表"（看视频哪几分钟）随定位一并作废。

每章的固定结构：

    章首    这一章解决什么问题。从动机讲起，把核心压成一两句第一性原理
            （例："编译器只是在选给谁生成机器码"、"make 只会比时间戳"），
            后面的一切从那一句推出来。
    节      概念 -> 原理（说人话，配图） -> 手把手操作 -> 实验 + 判据 -> 常见坑。
    章末    自检问题。每题都能用命令验证，不凭印象答。

具体规则：

1. **命令完整给，参数注明在管什么。** 每个参数第一次出现时用注释标清它的作用。
2. **代码完整给，逐行讲。** 关键行的讲解紧跟在代码块后；能跑的实验代码放
   labs/ 对应章目录，正文里贴并讲解。
3. **判据跟着实验走。** 没有判据的实验等于没做；每条判据都要能"注错见红"：
   故意改坏一处，判据必须失败。
4. **数字必须实跑。** 教程里的输出、体积、耗时一律来自本机或板上真跑，
   不照抄书。板上实测标注日期；板子不在线时不重跑、不编造，沿用已归档实测。
5. **能画图就画 ASCII 图。** 图最大的价值是画清边界：哪一步在内核里、
   哪一步在用户态、哪一步在编译期。不用中文显示宽度撑边框（换字体就错位）。
6. **真实描述优先于比喻。** 事物的身份和工作机制按真实情况讲
   （例：`$display` 是"内置系统任务，往标准输出写"），比喻至多一句辅助。
7. **原书勘误就地标注。** 讲到与原书不一致处，注明"原书写的是 X，实测是 Y"。
8. **说人话，思维连贯。** 每段讲完能顺着读下去，不跳步；术语第一次出现
   当场解释，或指到 fundamentals。

实验强度沿用四级：

    L1 复现   跑通并观察现象。占比小，只用来建立事实基础。
    L2 改造   给定目标，改现有代码，必须改出预期的可观测变化。
    L3 从零写 不看源项目源码，自己写一段完整的程序。
    L4 入项目 把这一层能力落进 project/，加出一整层代码。

## 二、基础知识（fundamentals/）

两类篇目，文件名都用 `NN_中文名.md` 排序：

- **讲解篇**（现有 00～12）：教程的前置知识。凡是不属于某章主线、以后还会
  反复出现的通用名词（ELF、sysroot、PLT/GOT、系统调用……），单开一篇，
  教程主线里只留跳转。讲解篇全部从 RISC-V / ysyx 那边搭桥讲起——只讲
  ARM/Linux 这边不一样在哪，不从零讲什么是寄存器。四步开头体例沿用：
  一句话本质 -> 你是从哪儿撞见它的 -> 它被什么逼出来 -> 关键细节。
- **手册篇**（13 起）：原书里罗列型知识点的整合。教程正文只讲原理
  （例：编译四步的原理），成堆的选项、标志位、语法细节提取成可检索的
  手册篇（例：GCC 选项手册、Makefile 语法与函数手册），用到了来查。

每篇配一个 `labs/00_basics/NN_xxx/check.sh`（手册篇视内容可免），
判据必须注错见红。一次跑全部：
`for d in labs/00_basics/*/; do bash "$d/check.sh"; done`（在 knowledge/ 下）。

## 三、实验与判据（labs/）

目录按教程章号组织：`00_basics/`（fundamentals 配套）、`01_hello/`、
`02_gcc/`、`03_makefile/`、`04_file_io/`……与 tutorials 的章一一对应。

- 实验源码入库，编译产物一律不入（.gitignore 白名单），由 check.sh 重建。
- 每个目录的 check.sh 从源码重建一切再逐条核对，末尾打印
  `N PASS / N FAIL / N SKIP`。
- 判据基线记录在根 README 进度节；判据变化的 commit 同步更新基线。
- 基线（2026-10-16 复核）：00_basics 十一套 + 06_text 合计
  323 PASS / 0 FAIL / 5 SKIP（04 篇 1 条缺 x86 32 位头，08 篇 4 条要 root）。

## 四、改写素材与流程

- 素材三件：原书 PDF（页码校准见 sources/README.md）、视频字幕
  （sources/视频字幕/，ASR 错词表同文件）、资料仓各章源码目录。
- 每章重写前先读齐三件，再吸收本仓旧稿的实测数据（旧稿数字都真跑过，
  弃文字不弃数据）；第 7～11 章无字幕，素材 = PDF + 源码 + project/ 对应层的
  TechReports 实测记录。
- 排期与状态唯一登记在 Engineering/Todo/knowledge教程化路线.md。
